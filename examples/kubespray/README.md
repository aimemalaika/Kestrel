# Kestrel on Kubespray (external add-on)

This directory is an **external add-on** for clusters provisioned with
[Kubespray](https://github.com/kubernetes-sigs/kubespray). It gives you a
turnkey Kestrel install on top of your own Kubespray inventory:

- the bundled Dex OIDC broker and Kestrel, installed with the Helm chart
- ingress TLS, using a CA and server certificate generated by the add-on
- kube-apiserver OIDC trust, wired through Kubespray's native `kube_oidc_*` variables

> **Not part of upstream Kubespray.** This add-on is not part of
> kubernetes-sigs/kubespray, there is no Kubespray fork, and nothing here assumes
> upstream will adopt it. You keep running your own, unmodified `cluster.yml`
> from your own Kubespray checkout. The add-on uses only the public Kubespray
> variables (`kube_oidc_*`), so it is version-independent: it works with any
> recent Kubespray release.

## Prerequisites

- **A Kubespray inventory** for the cluster, with a `kube_control_plane` group
  and a `k8s_cluster` group. You already run `cluster.yml` against it.
- **Ansible collections** used by the add-on:

  ```sh
  ansible-galaxy collection install -r requirements.yml
  ```

  This installs `community.crypto` (CA and certificate generation) and
  `kubernetes.core` (Kubernetes objects and `helm`).
- **The Kestrel Helm chart**, which is in this repo at `deploy/chart/kestrel/`.
  The add-on finds it relative to this directory by default. Run the playbooks
  from a checkout of this repo.
- **An ingress controller** in the cluster, and **DNS** for `kestrel_addon_host`
  pointing at it.
- **Helm and a working kubeconfig on the first control-plane node.**
  `deploy.yml` runs on `kube_control_plane[0]` and uses the Helm and Kubernetes
  modules there. Kubespray can install Helm for you with `helm_enabled: true`.

## Run order

There are three steps around your own `cluster.yml`. Run them in this order.

**1. Prepare: generate the CA and distribute it.**

```sh
ansible-playbook -i <inventory> prepare.yml -e kestrel_addon_host=kestrel.example.com
```

This runs on the control-plane nodes. It generates a CA and a server certificate
for `kestrel_addon_host` on the controller, copies the CA to every control-plane
node at `kestrel_addon_apiserver_ca_path`, and renders the `kube_oidc_*`
snippet at `kestrel_addon_group_vars_out`.

**2. Include the snippet, then run your own `cluster.yml`.**

Copy the generated file into your inventory's `k8s_cluster` group vars:

```sh
cp generated/kestrel-oidc.group_vars.yml <inventory>/group_vars/k8s_cluster/kestrel-oidc.yml
```

Then run **your** Kubespray playbook as you normally would:

```sh
ansible-playbook -i <inventory> <your-kubespray-checkout>/cluster.yml -b
```

The apiserver now starts with the OIDC flags. The CA file must already exist
on the nodes, which is why prepare runs first.

**3. Deploy: install the Kestrel Helm release.**

```sh
ansible-playbook -i <inventory> deploy.yml
```

This runs on `kube_control_plane[0]`. It creates the namespace and the TLS
Secret, then installs the chart with `ingress.tls.mode=secret`. If
`kestrel_addon_verify_apiserver` is `true` (the default), the playbook also
checks that the apiserver manifest contains the expected `--oidc-issuer-url`.
The manifest only exists after step 2, so the check does nothing on the first
prepare run. To confirm the flag landed, re-run `prepare.yml` after your
`cluster.yml`. The rerun is idempotent.

Re-running the playbooks is safe. The CA and key tasks reuse existing files in
`kestrel_addon_local_certdir`, and Helm upgrades the release in place.

## Variables

Set these in your inventory, with `-e`, or in a vars file. Defaults come from
`roles/kestrel_addon/defaults/main.yml`.

| Variable | Default | Purpose |
|---|---|---|
| `kestrel_addon_host` | `""` (**required**) | Public host for the ingress. The OIDC issuer is `https://<host><dex_path>`. |
| `kestrel_addon_ingress_class_name` | `""` | IngressClass name, for example `nginx`. Empty omits `ingressClassName`. **Set it** unless your cluster has a default IngressClass, or the ingress will not be served. |
| `kestrel_addon_dex_path` | `/dex` | Path for the bundled Dex issuer. Must match the chart's `dex.path`. |
| `kestrel_addon_oidc_client_id` | `kestrel` | OIDC client ID, written to `kube_oidc_client_id`. |
| `kestrel_addon_namespace` | `kestrel` | Namespace for the Kestrel release and TLS Secret. |
| `kestrel_addon_release_name` | `kestrel` | Helm release name. |
| `kestrel_addon_chart_path` | `<repo>/deploy/chart/kestrel` | Path to the Kestrel chart. |
| `kestrel_addon_image_repository` | `ghcr.io/aimemalaika/kestrel` | Kestrel image repository. |
| `kestrel_addon_image_tag` | `1.0.0` | Kestrel image tag. |
| `kestrel_addon_admin_user` | `admin@kestrel` | Bundled Dex admin login user. |
| `kestrel_addon_admin_groups` | `["kestrel-admins"]` | Groups for the admin user. |
| `kestrel_addon_github_client_id` | `""` | GitHub OAuth client ID. Empty leaves GitHub login off. |
| `kestrel_addon_github_client_secret` | `""` | GitHub OAuth client secret. **Store in ansible-vault.** |
| `kestrel_addon_github_orgs` | `[]` | GitHub orgs allowed to sign in. |
| `kestrel_addon_apiserver_ca_path` | `/etc/kubernetes/pki/kestrel-oidc-ca.pem` | Where the CA is placed on control-plane nodes. Feeds `kube_oidc_ca_file`. |
| `kestrel_addon_local_certdir` | `<playbook dir>/generated/pki` | Controller-side directory for key material (`ca.key`, `ca.pem`, `tls.key`, `tls.crt`). |
| `kestrel_addon_cert_days` | `3650` | Validity of the CA and server certificate, in days. |
| `kestrel_addon_tls_secret_name` | `<release>-tls` (`kestrel-tls`) | Name of the `kubernetes.io/tls` Secret. |
| `kestrel_addon_oidc_username_claim` | `email` | `kube_oidc_username_claim`. |
| `kestrel_addon_oidc_groups_claim` | `groups` | `kube_oidc_groups_claim`. |
| `kestrel_addon_group_vars_out` | `<playbook dir>/generated/kestrel-oidc.group_vars.yml` | Where the `kube_oidc_*` snippet is rendered. |
| `kestrel_addon_verify_apiserver` | `true` | Check the apiserver manifest for the OIDC issuer flag. |

## GitHub login (optional)

By default you get **password-only** login through the bundled Dex. To enable
"Log in with GitHub", set `kestrel_addon_github_client_id` and
`kestrel_addon_github_client_secret`, and store the secret encrypted with
ansible-vault:

```sh
ansible-vault encrypt_string --name kestrel_addon_github_client_secret
```

Paste the output into your inventory or a vars file. The secret is never
written to disk. `deploy.yml` passes it to Helm inline, with `no_log` on
the task. Leave the client ID and secret empty to keep password-only login.

## What it creates

- **On the controller:** a CA (`ca.key`, `ca.pem`) and a server certificate
  (`tls.key`, `tls.crt`) for `kestrel_addon_host`, in `kestrel_addon_local_certdir`.
- **On control-plane nodes:** the CA at `kestrel_addon_apiserver_ca_path`
  (root-owned, mode `0644`). The public CA certificate is the only file copied there.
- **In your inventory:** the `kube_oidc_*` snippet that you copy into
  `k8s_cluster` group vars. Kubespray then sets the apiserver `--oidc-*` flags:
  `kube_oidc_auth`, `kube_oidc_url`, `kube_oidc_client_id`, `kube_oidc_ca_file`,
  `kube_oidc_username_claim`, `kube_oidc_groups_claim`.
- **In the cluster:** the `kestrel` namespace, a `kubernetes.io/tls` Secret
  (`kestrel-tls`) holding the server certificate and key, and the Helm release
  `kestrel`, installed with `ingress.tls.mode=secret` and bundled Dex enabled.

> **Keep `generated/` out of git.** It holds the CA private key and the server
> private key. Do not commit it, and do not copy it onto the nodes. Only the
> CA certificate (`ca.pem`) goes to the control-plane nodes.

## Uninstall

1. Remove the Helm release and the namespace. Deleting the namespace also
   removes the TLS Secret.

   ```sh
   helm uninstall kestrel -n kestrel
   kubectl delete namespace kestrel
   ```

2. Remove the OIDC wiring from the cluster. Delete the copied
   `group_vars/k8s_cluster/kestrel-oidc.yml` from your inventory, then re-run
   your `cluster.yml`. Kubespray re-renders the apiserver manifest without the
   `--oidc-*` flags.

3. Remove the CA from each control-plane node:

   ```sh
   sudo rm /etc/kubernetes/pki/kestrel-oidc-ca.pem
   ```

   Adjust the path if you changed `kestrel_addon_apiserver_ca_path`.

4. Optionally, delete the controller-side `generated/` directory. Do this only
   after the cluster no longer needs the CA. Issuing a new CA means prepare
   must run again, with a fresh `kube_oidc_ca_file`.

## Trust

The apiserver trusts the issuer through `kube_oidc_ca_file`, which points at
the CA this add-on generated. Clients must trust the same CA. The server
certificate for the issuer is signed by this CA, so a browser or `kubelogin`
that does not trust it cannot complete the login.

For the rest of the trust model, including the four `--oidc-*` settings
Kestrel and the apiserver must share, see
[`../oidc/apiserver-trust.md`](../oidc/apiserver-trust.md).
